A camada que completa o ServiceNow.

Vocês já têm o sistema de registro (ServiceNow / Now Assist) e o controle de máquina (Bomgar). O que falta para fechar o chamado repetitivo sozinho é a camada de raciocínio e execução que opera por cima do que vocês já rodam — não no lugar dele.

O que ouvimos na conversa

Para que esta proposta respeite a realidade de vocês, não a nossa.

  • A Petrobras está no início da jornada de IA e a estratégia é manter tudo dentro do ServiceNow (Now Assist / Virtual Agent), evoluindo primeiro um assistente interno no Teams — WhatsApp vem depois.
  • O controle da máquina do usuário hoje é via Bomgar; há Ansible e um motor de regras no ecossistema.
  • O WhatsApp é valorizado, mas para resolver incidentes — não para virar mais um canal de dúvida.
  • Qualquer aquisição passa por edital e ampla concorrência — nada de contratação direta.

Conclusão: a porta de entrada não é trocar de plataforma. É achar onde a IA de vocês para — e completar dali.

Onde o Now Assist para — e onde nós entramos

Orquestrar não é resolver. O ServiceNow conduz o fluxo; a resolução de ponta no endpoint é outra camada.

Sobre o Bomgar — sim, dá para integrar

A pergunta que ficou na call, já respondida.

O BeyondTrust Remote Support (o produto que vocês chamam de Bomgar) expõe uma API REST documentada e atual (linha 26.x). Pela documentação oficial, ela permite a aplicações de terceiros emitir comandos, orquestrar sessões de suporte remoto e puxar dados de relatório — exatamente os ganchos de que um agente de IA precisa para executar a remediação no endpoint de forma programática.

Na prática: o agente Superclawman raciocina sobre o chamado, decide a ação e aciona o seu Bomgar para realizá-la — a integração roda por cima da ferramenta que vocês já têm.
